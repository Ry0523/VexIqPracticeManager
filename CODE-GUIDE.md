# Code Guide

This guide maps the hand-maintained source. Do not edit `apps-script/dist-iq/` or `apps-script/dist-v5/` directly; `build-apps-script.js` generates those bundles from the source modules below.

## Runtime Flow

`index.html` loads the selected game definitions and practice views, then the rule modules, domain models, storage, and UI controllers. `game.js` selects the active definition. `app.js` coordinates the page and event state; specialized UI controllers mount into the page and call the domain models. In the browser, modules publish named globals; under Node.js, the same modules expose CommonJS exports.

Persisted event data is validated by `event.js`. Posted results are captured in `history.js`, which is the durable analysis/export record. V5 practice field state is stored as opaque `gameData`; the matching game definition validates and scores it. Shared saves pass through `storage.js` and are merged by `changes.js` on the Apps Script server.

| Browser coordinator | `app.js` | Event state, navigation, setup/match workflows, analysis, settings, and connections between UI and models. |

## Module Contracts

- `EventRules` combines `MatchScoring`, `MatchScheduling`, and `TeamRoster` for existing consumers. New code should import the narrow module it owns when practical.
- JSDoc imports reference `types.d.ts`; use those named interfaces instead of bare `object` for shared contracts. Keep game-only payloads generic (`unknown` in shared code) and narrow them inside the owning game module.
- Game definitions own game-specific score schemas and rules. Optional `practice` capabilities describe supported modes, scrimmages, and field APIs; game practice views implement `render`, `read`, `update`, and `handleClick`.
- `History.practiceRecord` accepts common run metadata plus optional opaque `gameData`. It delegates custom field validation/scoring to the record's game definition; generic history code must not inspect game-specific field structure.
- `EventStorage` is the persistence boundary. Local storage uses IndexedDB; the shared app uses Apps Script RPC, revision checks, and change-based merges.

## Verification

- `npm test` runs the Node.js unit/model suites.
- `npx playwright test --workers=1` runs browser workflows.
- `npm run build:iq` builds the IQ deployment; `npm run build:v5` builds V5.
